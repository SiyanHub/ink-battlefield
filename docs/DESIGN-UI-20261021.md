# 配装说明与战斗反馈设计 · 2026-10-21

## 这次解决的问题

配装页原先只有名称和下拉框，玩家无法知道换一件武器意味着什么。现在两个主武器位置分别展示用途、左键操作、基础伤害单位、弹匣容量、换弹时间和射程。单机使用 `damage`，自由试笔与联机使用 `pvpDamage`；霰弹与喷墨明确标注“每弹丸”，蓄力武器标注满蓄伤害。三发点射保留每发伤害，不合成为虚构的 DPS。

数值直接取自内容定义，页头说明不含成长、弱点与距离修正。选择武器后通过 Controller 的 changed 回调立即更新说明，App 恢复对应下拉框焦点。第二栏留空时说明滚轮会跳过此槽。近战与职业技能保留在同一块的底部，避免再增加一张高卡片。

战斗反馈采用暖纸、石墨和克制的蓝色。中央仅出现短暂的命中圈和“命中”文字；击倒文字放在准星下方，最多三条。右上角显示真实 Boss 名称与生命，避开中央射击区域。左下低血提示一直可见，不采用循环闪烁；受伤边缘只短暂出现。

## 数据与生命周期

- `BattleFeedback` 消费公开的 `GameFrame`，不读取输入意图作为命中证据。只有本人的 hit/death 事件生成命中/击倒，指向本人的 hit 生成受伤提示。
- 使用会话事件 ID 高水位去重，不保留无限事件集合。命中持续 0.32 秒、受伤边缘 0.6 秒、击倒 2.4 秒；击倒队列硬上限三条。HUD 每次替换其 HTML，没有累积节点。
- Controller 停止/替换会话时 reset；新会话的相同事件 ID 可以正常使用。同一会话进入新遭遇、模拟时间回到起点时清掉瞬时反馈和换弹观察，但保留会话 ID 高水位。
- 换弹的剩余秒数来自 `reloadUntil - snapshot.time`。进度以首次观察到该次换弹为起点，并在换枪、取消或结束时清空。这可兼容成长缩短、自动换弹以及恢复会话；中途加入时，进度从客户端观察开始，而剩余时间仍以快照为准。
- 蓄力使用 `chargeStarted`、武器 `charge` 和玩家快照中 `quickcharge` 成长；与模拟相同地限制最短时长。满蓄显示“松开射击”。
- Boss 由内容中 `boss` 标记识别，仅展示存活敌人，最多两个；名称、当前与最大生命来自快照。
- 自由试笔与其他模式都渲染 `objective.title / description / progress / target`，不覆盖真实练习内容。
- “减少镜头晃动与受伤闪边”开启后不生成受伤边缘节点，保留静态伤害/低血文字与玩法信息。系统减少动态偏好同样隐藏该边缘；所有新反馈均无循环动画。
