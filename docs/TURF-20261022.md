# 双队涂地与油墨呈现 · 2026-10-22

本轮增加一个无需建房即可游玩的双队涂地入口，把原有4分钟涂地规则与电脑参战、固定队色、实时覆盖战况和厚油墨呈现连成完整流程。仅修改本地工作区，未提交、推送或部署；README 中的在线链接仍对应此前发布版本。同日较早的[体验优化记录](OPTIMIZATION-20261022.md)及其分项证据保持原样。

## 进入方式与存档边界

首页“双队涂地”进入配装与选图页。可选笔记本工地（`construction`）、折纸街区（`street`）、画室堡垒（`fortress`），四职业、16件画具继续开放。单人局固定2对2：玩家和一位电脑队友为蓝墨队，两位电脑对手为朱墨队。电脑使用正式玩家实体和公开输入接口，经过共享的移动、耗弹、换弹、技能、伤害与复活规则。

单人涂地的 Esc / P 打开暂停菜单，玩家、电脑、弹体、比分与倒计时同时冻结；恢复后继续同一张画页。倒下5秒后自动复活，倒下期间可调整下一次复活装备。结算提供双方结果、最终覆盖、观察/保存战场和“再涂一局”，重开从240秒及干净地图开始。这是独立的临时竞技会话，不写入战役检查点、成长或战绩，也不消耗已有战役进度。

配装页另有“和朋友局域网对战”，首页原有LAN入口也保留。真人房间支持2–8人，不自动补电脑；涂地模式强制分队，蓝、朱双方都有人且全员准备才能开局。联机菜单继续比赛。当前源码的 `build:cloud` 包含单人电脑涂地，单人玩法不依赖房间服务器；云端构建的LAN页仍提供本地主机启动说明，没有新增公网房间服务。

## 统一墨色与判分

共享色表位于 `src/shared/ink.ts`：

| 队伍 | 内部ID | 墨色 | CSS |
|---|---|---|---|
| 蓝墨队 | `blue` | `0x1977bd` | `#1977bd` |
| 朱墨队 | `red` | `0xe05b35` | `#e05b35` |

同队各职业的角色识别色、枪械/近战墨迹、弹道、投射物、爆破子弹和技能使用固定队色。队伍环、标记与文字继续辅助辨认。单机战役和自由试笔的玩家使用固定职业色，取消每发轮换的彩虹墨迹。

比分是各队已占有面积除以整张地图的有效可计分地板面积。未染色地板保留在分母中，HUD 显示蓝、朱与留白三部分；不会把两队当前已涂区域重新归一成100%。墙面和角色染色不计面积，击败数没有额外面积分；击败后落到地面的实际墨迹仍按正常格子归属计算。覆盖敌队墨迹会立即转移该格面积。不可染色的遮挡区域从分母排除，边缘不足整格的区域按实际面积计入。

规则每个60Hz步进更新双队比分，包括双方为零的情况。比赛在第14400个步进，即240秒截止；该步进的开火、投射命中和覆色先完成，再刷新面积和判定胜负。面积较高的一队胜，差值在浮点容差内为平局，没有胜者。100%只是覆盖上限，不触发提前胜利。联机客户端随服务器20Hz权威帧获得比分。

全图统计维护总有效面积及各owner已占面积，覆盖时只转移实际变化格子的面积；恢复快照时重建账本，返回的分数对象独立于内部状态。区域占点仍使用区域扫描。这使实时涂地比分无需每帧遍历全图地板。

## 油墨呈现与开销边界

逻辑格子作为连续色场的采样点，呈现为不透明、相邻融合的油墨区域，并加入边缘堆积的明暗、细微颜料起伏和少量飞点。两队交界保留颜色归属，新覆色格中心保持新队颜色。视觉边缘和飞点不改变规则面积，判分仍由服务器/本地共享规则的格子归属决定。

每个表面复用固定32×32 `ImageData` 缓冲、格子颜色数组与坐标权重，只更新受到变化影响的有界像素块；清空、新局和完整恢复均有回归。相邻连片、跨块覆色、删除、顺序变化与画布边缘的增量结果逐字节对照完整重画。冲击飞点使用固定容量池。

`CanvasTexture` 的更新仍会上传对应表面纹理；局部CPU重绘不等于GPU局部纹理上传。`PaintRaster.apply` 仍检查该表面的输入快照，不能描述为整个渲染链路只遍历变化格。CPU光栅、Canvas传输或单组件计时均不包含整局全部WebGL工作，也不替代有效前台FPS验收。

正式Chrome证据 `artifacts/ink-20261022/raster-pixels-chrome.json` 包含两种 `willReadFrequently` 配置共18组完整/增量对照，全部0像素差异；65536个内部采样像素没有透明漏底，单格朱墨覆色中心仍保持朱色。该选项只是浏览器提示，不据此推断实际Canvas后端。

Chrome的1024×1024纹理、7744格组件计时如下，原始记录为 `artifacts/ink-20261022/raster-benchmark-chrome.json`；包含CPU光栅与Canvas写入，不含WebGL纹理上传和整场绘制：

| 单次更新场景 | 平均耗时 | P95 |
|---|---:|---:|
| 逐步增加1–10个相邻格 | 1.322ms | 3.0ms |
| 满表面更新1个格 | 2.057ms | 4.5ms |
| 满表面更新10个相邻格 | 3.092ms | 4.5ms |
| 满表面更新10个分散格 | 13.135ms | 15.9ms |
| 未变化的完整快照 | 0.135ms | 0.2ms |

未变化快照没有像素写入，分散变化比相邻变化涉及更多脏块；本次完整填满表面耗时175.6ms。这些是局部工作量的实测，不是目标帧率已经达标的证据。较早的 `raster-benchmark-native*.json` 保留为64→32像素块优化对照，不与Chrome结果混用。开发检视页 `ink-review.html` 可复核连续油墨与单格覆色效果；该页不作为生产入口，实际3D三面截图为 `artifacts/ink-20261022/ink-review-material-chrome.jpg`。
